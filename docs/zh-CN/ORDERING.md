# 订单检查与灵活下单规模

简体中文 · [English](../ORDERING.md)

TradePilot 接受灵活的下单意图，但执行前总会把它换算成明确的 Trading 212 股数。

<a id="supported-inputs"></a>
## 支持的输入

标的可以用 Trading 212 ticker、市场代码、ISIN、公司名或部分名称表示。TradePilot 会解析出券商的标的，确实有歧义的匹配会被拒绝；一个 ISIN 在多个交易所上市时，会列出各个上市地及其币种供你选择。

典型请求：

```text
Buy 0.2 shares of NVDA in Demo.
Buy about €100 of Nvidia in Live.
Use 20% of my available cash to buy Apple.
Sell half of my Nvidia position.
Sell all currently tradable Apple shares.
Buy 0.5 NVDA at a 220 USD limit.
Prepare the order only; do not submit it.
```

<a id="sizing-modes"></a>
## 下单规模模式

<a id="exact-quantity"></a>
### 指定股数

请求的股数原样保留，并根据所选标的和当前账户状态做校验。

<a id="target-monetary-amount"></a>
### 目标金额

目标金额按提供的参考价换算成股数。请求的币种和标的报价币种不同时，还需要提供汇率。

算出的股数向下取整，换算时不会有意超出目标金额。

<a id="percentage-of-available-cash"></a>
### 可用现金的一定比例

买入时，TradePilot 读取账户当前的可用现金，按请求的比例算出金额，再换算成股数。

账户币种和标的报价币种不同时，需要提供汇率。

<a id="percentage-of-held-position"></a>
### 持仓的一定比例

卖出时，比例按**总持仓**计算，而不是只按当前可交易的那部分。

如果请求的股数大于当前可交易数量，TradePilot 会拒绝这次换算，而不是悄悄改变请求的含义。

<a id="all-currently-tradable-shares"></a>
### 当前全部可交易股数

`all_available` 是明确的卖出模式，卖出 Trading 212 当前显示为可交易的全部数量。

<a id="risk-at-the-stop-loss"></a>
### 按止损亏损定规模

买入时，`risk` 按价格跌到止损价时这笔订单会亏多少来决定规模。给出 `stopLossPrice`（标的币种），以及 `amount`（账户币种）或占账户总值的 `percent` 二者之一：

```json
{ "mode": "risk", "percent": 1, "stopLossPrice": 200 }
```

入场价取这笔买单可能成交的最差价格，所以到止损价的亏损永远不会被低估：限价单或止损限价单取限价；止损单取触发价、参考价和最新价中最高的一个，因为价格已经越过的触发价会立刻成交（止损单触发后变成市价单，所以跳空后仍可能高于触发价成交；它的检查结果会提示这一点）；市价单取参考价和最新价中较高的一个。最新价取自持仓；没有持有的标的，取自行情源。订单编辑器在你修改价格时也按同样方式计算亏损。草稿的参考价始终是市场价格，即给出的价格和最新价中较高的一个，而不是止损单的触发价，这样检查时仍能区分挂在市价之上的止损单和会立刻触发的止损单。市价单或止损单每次检查时，如果最新价更高，就把参考价提高到最新价并记下当时的时间，这样 `POLICY_MAX_REFERENCE_AGE_SECONDS` 看到的是刚核对过的价格。草稿带着止损价和预算（`riskBudget`），检查时会按当时的价格再算一次亏损（没有持有的标的会重新读取行情源报价；如果你的持仓都推算不出它的汇率，也会重新读取汇率；如果行情源当时没有报价，或者不再提供它之前给出的汇率（你自己给出的汇率会保留），或者没有任何汇率能把亏损换算成账户币种，或者根本没有价格能给这笔订单估值，这笔买单会以 `RISK_CHECK_UNAVAILABLE` 被拒绝，而不会按旧价格检查或干脆不检查）：如果价格变动或股数被修改，导致止损时的亏损超过预算，检查会在你确认前提示；订单价格，或能立即成交的订单的市场价格（不包括还在等价格涨到触发价的止损买单），已经处在止损价或以下时，也会同样提示。发送时还会按那一刻的价格再检查一次，报价和汇率直接从行情源读取，不用它一分钟的缓存：如果止损时的亏损比检查时显示的更多（预算，或检查提示的更大亏损），或者价格在此期间已跌到止损价，就不会发送任何订单，结果为 `RISK_CHANGED`；组件会把订单留在编辑器里，下一次检查会按新价格显示。股数等于预算除以从入场价到止损价的跌幅，并像金额一样换算成账户币种。股数向下取整，且不超过可用现金能买的数量；如果是现金限制了股数，说明里会写明，并给出较小的亏损。拿不到账户的可用现金或账户币种时，按风险定规模的买单会被拒绝，因为它的预算无法换算，股数也无法封顶。

订单篮（`review_order_basket`）会把按风险定规模的买单当作普通订单：它会丢掉预算，所以只有单独检查这笔买单时，才会检查止损时的亏损。

止损不是这笔订单的一部分。买单成交后再设置，例如用 `review_protective_orders`，或在该持仓页面上点**设置止损**。跳空可能让止损单以低于止损价的价格成交，所以亏损可能大于预算。

订单编辑器会在你修改股数或价格时显示止损时的亏损，超过预算时会标出来。

<a id="review-flow"></a>
## 检查流程

```text
Flexible request
  ↓
resolve broker instrument
  ↓
read account/position when required
  ↓
calculate exact quantity
  ↓
editable order draft
  ↓
server validation
  ↓
short-lived one-time confirmation
  ↓
explicit user confirmation
  ↓
Trading 212 write
```

订单编辑器同时显示原始的规模规则和算出的股数。如果手动修改了股数，界面会标记为已修改，并提供恢复为计算值的操作。

订单可以带一个 `thesis`，也就是你下这笔单的理由。它会显示在检查页上，但从不发送给 Trading 212；订单被接受后，它会连同订单 id 一起保存到交易日志（[JOURNAL.md](./JOURNAL.md)）。

### 这笔单会带来什么变化

最终确认页的**成交后**一栏，根据这次审核读到的持仓和现金，算出这笔单会带来的变化，不为此额外读取任何数据。所有金额都按账户币种计算（`app_prepare_order` 结果里的 `impact`，模型也会收到一行说明）：

- **持有股数**：成交前和成交后。
- **占账户比例**：这项持仓的价值占账户价值的比例，成交前和成交后。买入加上付出的金额；卖出后剩下的股份按原来的每股价值算。账户价值只因手续费而变化。
- **可用于交易的现金**：买入扣掉、卖出加上的金额，再减去换汇费。
- **已实现盈亏**（卖出时）：卖出所得减去这部分股份对应的持仓成本，也就是 Trading 212 按平均成本计算的方式。
- **换汇费**：标的和账户币种不同时显示，最多为金额的 `FX_FEE_RATE`；如果用该币种的余额支付，就不用换汇。
- `TAX_YEAR_START=04-06` 时，卖出会附上英国的匹配规则：当天或卖出后 30 天内买入的同一公司股票，会先和这次卖出匹配；如果这次卖出是亏损，还会提醒：30 天内买回，这笔亏损就会抵掉那次买回。

这些都是按审核时的价格估算的，以实际成交和 Trading 212 的结单为准。

<a id="price-checks"></a>
## 价格核对

限价或止损价比最新价高或低十倍时会被拦下（`PRICE_OUT_OF_RANGE`），因为这几乎总是单位弄错了，比如按便士报价的标的输入了英镑价格。不那么离谱的情况会在检查页上提示：

- `STOP_ALREADY_TRIGGERED`：止损价已经达到或越过最新价，订单会立刻触发；
- `LIMIT_FILLS_AT_ONCE`：买入限价比最新价高 2% 以上（或卖出限价低 2% 以上），会在接近市价处立即成交；
- `PRICE_FAR_FROM_LAST`：价格与最新价相差 30% 以上；
- `STOP_SLIPPAGE`：每一笔止损单都会提示，它触发后会变成市价单，所以跳空后可能越过触发价成交。

止损买单的止损价高于市价时，按止损价估值，这样 `MAX_ORDER_NOTIONAL`、现金检查和规则看到的是它触发后可能花的钱。

<a id="following-up-an-order"></a>
## 跟进订单

`get_order_status` 按 id 查询单个订单：仍在挂单（以及已成交多少），或者最终结果如何，并附上成交明细。`review_order_cancel` 会在组件里打开挂单的撤单确认，由你确认；模型不能自己撤单。`get_trade_history` 加上 `includeUnfilled` 时，也会列出已撤销、被拒绝或已过期的订单。

<a id="price-and-fx-timestamps"></a>
## 价格和汇率时间戳

按金额下单时应提供当前参考价，需要时还要提供当前汇率。可选的时间戳字段有：

- `referencePriceAt`
- `fxRateAt`

最终确认页会显示账户快照的核对时间；参考价缺少时间戳，或早于应用使用的时效阈值时，会给出警告。

时间戳只是参考信息，不是价格保证。市价单仍可能以偏离参考价的价格成交。

<a id="unknown-write-results"></a>
## 结果未知的写操作

Trading 212 写请求只发送一次。网络超时或含糊的服务端响应不会触发自动重试。唯一的例外是被 Trading 212 以 429（限流）拒绝的写请求，Trading 212 并没有执行它：它会在 Trading 212 要求的延迟后再发送一次（至少 2.1 秒，因为限价单和止损单每 2 秒只允许一次请求），延迟超过 15 秒时会报告。

同一环境上的确认逐个发送，所以同时确认的两笔订单不可能都通过每日限额检查。

写操作结果未知时，TradePilot 会创建一条短期有效的核对记录。界面随后可以做一次**只读**检查：

- 找到匹配的待处理订单 → 不要重新提交；
- 市价单对应的持仓变动了请求的数量 → 很可能已执行，任何重试之前先核对券商的操作记录；
- 没有确凿证据 → 保持“不确定”，在采取进一步行动前先到 Trading 212 核实。

核对操作从不重复原来的写请求。

<a id="instance-limits"></a>
## 实例限制

自托管用户可以配置：

```env
DEFAULT_TRADING_ENV=demo
MAX_ORDER_NOTIONAL=5000
MAX_ORDER_QUANTITY=100000
```

`DEFAULT_TRADING_ENV` 只在请求没有明确选择 Demo 或 Live 时生效。

`MAX_ORDER_NOTIONAL` 按账户币种计算；其他币种的订单按持仓推算出的汇率折算，没有任何持仓用到的币种则按行情源的汇率折算。完全拿不到汇率时，开启上限期间这笔订单会被拦下；可以传入来自有日期来源的 `fxRate` 和 `fxRateAt`。把任一应用层上限设为 `0`，就关闭对应的 TradePilot 限制。Trading 212 自身的标的/账户约束和明确确认仍然有效。
