# 组合分析

简体中文 · [English](../ANALYTICS.md)

TradePilot 根据 Trading 212 的数据确定性地计算组合指标，模型不需要自己做算术。这些工具都是只读的，例外只有：`manage_history_export` 可以申请生成报表（如果已有一份涵盖该时间段的报表，就直接给出那一份，不会再生成第二份），`manage_trade_journal` 和 `manage_watchlist` 会写入 TradePilot 自己的存储。

<a id="the-holdings-map"></a>
## 持仓热力图

仪表盘可以把持仓显示成列表或热力图；在宿主允许本地存储时，会为每位查看者记住所选的方式。

- **列表**保持 Trading 212 的顺序，直到你在**排序**菜单里选择或点击列标题来排序：市值或盈亏从大到小、从小到大，当日涨跌从高到低、从低到高，或名称 A 到 Z。点击列标题，第一次从大到小排，第二次从小到大排，第三次恢复 Trading 212 的顺序。无论哪个方向，缺少所排数值的持仓都排在最后。手机上的卡片也按同样的顺序排列。
- **热力图**给每个持仓一块方格，面积等于它按账户币种计的市值，从大到小排布，让每块方格尽量接近正方形。颜色表示**当日涨跌**（相对前一收盘价的变化，与“日涨跌”列相同）或**持有以来**的收益（未实现盈亏相对于市值减去这部分盈亏，按账户币种计，所以包含汇率变动）。绿色为涨、红色为跌，幅度越大颜色越深；色阶的上限取 1%、2%、3%、5%、10%（当日）或 5%、10%、25%、50%、100%（持有以来）中能涵盖五分之四持仓的最小值，这样一只大涨大跌的持仓不会让其余持仓都显得没有颜色，超出上限的按最深颜色显示。每块方格里的文字用正文颜色并写出正负号，所以颜色从来不是唯一的读法；没有数据的持仓用斜纹表示。方格里在放得下的范围内显示代码、涨跌幅和金额，悬停时和屏幕阅读器会给出完整描述（名称、涨跌幅、金额、市值和占持仓比例）；点击会打开该持仓（小到看不见的方格键盘导航会跳过，可以从列表打开该持仓）。读取当日涨跌期间，当日模式的方格保持中性色并显示“…”；读不到当日涨跌，或没有任何持仓有当日涨跌时，热力图按持有以来的收益着色，热力图和排序里都不再提供当日选项。

<a id="the-dividend-calendar"></a>
## 分红日历

“收入”标签页的日历显示本月和之后 11 个月。每个月的柱子分为已到账部分（实心，只有本月会有）和预计部分（斜纹），柱子下面按日期由近到远列出各笔分红。只要所选期间截止到本月（该标签页的各个期间都是如此），日历就会显示。

- **哪些分红。** 每个持仓从一年前本月第一天以来的分红，这样某个持仓去年在本月派的那笔分红（今年本月又该派了），即使当时比今天的日期早几天到账，也仍在范围内。与某个派息日第一笔记录相隔十天以内的记录都算作这次派息的一部分：股数相同的会相加（常规股息之外的特别股息、调整）；股数不同的，视为对持仓不同部分派发的同一笔分红。单独一天的更正（金额为零或负数）计入它之前的那个派息日。
- **多久一次。** 派息日之间间隔的中位数：大约一个月、一个季度、半年或一年。只有派息日确实支持时，持仓才会被认定为每周或每两周派息（至少六个派息日，其中四分之三相隔不到三周，相隔三天以内的记录算作一次）；只有一个派息日的按每年一次计。
- **多少。** 最近一年的派息日（季度派息的取四次，即使读到的这一年有五次），按每股金额乘以现在的持股数计算。这些是 Trading 212 的净派息，所以已扣除预扣税，并按账户币种计。年内才买入的持仓，派息日次数比它的派息频率少，所以按全年应有的次数放大。这一年的金额会分摊到接下来一年的各笔分红上：一年前对应的派息日存在时，按那次的比例分摊，这样小额的中期股息和大额的末期股息仍保持原样；不存在时按平均派息日分摊；各笔加起来与总额精确到分。
- **什么时候。** 从上一个派息日按间隔往后推（派息日大多落在月末的持仓会保持在月末）。本月早些时候应到但还没到账的分红仍算作预计，并标为应到账；本月已经到账的，下一次预计在一个完整间隔之后，对一年一派的持仓来说会落在日历最后一个月之后，所以日历各月加起来可能少于预计总额，标签页会注明这一点。
- **它不知道的。** Trading 212 的 API 不提供已公告的分红，所以公司提高、削减、暂停或推迟派息，要等实际派发后才会体现。从那天以来没有派过息的持仓，不会预计任何分红。日期指分红到账的时间，不是除息日。

持仓页会按同样的规则列出接下来预计的四笔分红和派息频率，读取分红也从同一天开始。

<a id="gain-by-instrument"></a>
## 收益来源（按标的）

“收益”标签页的**收益来源（按标的）** 图，以及 `get_portfolio_performance` 里的 `attribution`，把期间收益按标的拆开：每个标的一根条，从共同的零线出发，盈利向右、亏损向左，盈利最大的排在最前，上方是合计。标的超过十个时，只画盈利和亏损最大的十个，点**显示全部**后才全部显示。点每个标的的名称会打开它的页面，表格视图给出每根条背后的数字。

- **按期间**（1 个月、3 个月、今年、12 个月），一个标的的收益 = 现在的市值 − 期初市值 − 买入从账户支出的金额 + 卖出收回的金额 + 股息。Trading 212 只报告今天的持仓，所以期初持仓是当时的持股数（今天的持股数，减去此后买入的，加上此后卖出的），按期间第一天之前行情源的收盘价计算；收盘价取自持仓页价格图读取的那一年数据（12 个月期间会多读几天）。买入和卖出用 Trading 212 自己给出的每笔成交的账户币种金额（`walletImpact.netValue`），股息用它的净派息，现在的市值也用 Trading 212 的。期间从第一天的零点（UTC）开始。
- **汇率。** 期初市值按今天的汇率换算，即 Trading 212 自己对持仓的估值所隐含的汇率（如果该标的此后已卖出、账户里也不再持有该币种，则用它自己的成交所隐含的汇率；成交的账户金额含费用时会略有偏差）。所以期初所持部分的币种涨跌不计入收益，此后买入部分的币种涨跌则计入。
- 每根条旁边的**收益率**是相对于投入资金的收益：期初市值加上买入金额。
- **全部历史**没有期初可以估值，所以每个标的的收益采用 Trading 212 自己的核算：卖出的已实现盈亏、当前持仓的未实现盈亏，加上股息。在读取的历史之前买入的股份，按买入成本计算。
- **未计入的。** 期初持有、但读不到收盘价的标的会列为未计入，原因与价格图给出的一致（没有行情源、没有代码、收盘价单位不同，或期初之前十天内没有收盘价）；超时的标的（收盘价每次请求四个，五秒后不再发起新的读取）会在下次读取，那时其他标的已有缓存。股数对不上的标的（倒推出的期初股数少于零，比如股份不经成交就转入转出），或期间内有拆股或其他公司行动的标的（期初和现在的股数单位不同），也会列出。如果订单或股息历史没有读到期初（调高 `maxPages`），或者期间在现在之前就已结束，就没有收益拆分：`attributionMissing` 说明是哪种情况（`history`、`period`，或读取失败时为 `data`），`attributionProblem` 说明原因。

<a id="drawdown"></a>
## 回撤

收益图的**回撤**视图，以及 `get_portfolio_performance` 里的 `timeWeighted.drawdown`，显示时间加权收益从高点回落了多少。每个记录日的值 = 截至当天的增长（1 加收益率）÷ 截至当天任一记录日的最高增长 − 1：创新高的那天为 0，比高点低 8% 的那天为 −0.08。因为是按时间加权收益计算的，出金不算下跌，入金也不算上涨。

- `max` 是其中最深的一次回落，以负的小数表示；`peak` 和 `trough` 分别是回落前的高点日期和最低点日期；`recovered` 是最低点之后第一次回到那个高点的日期，没有 `recovered` 表示还没有回本。距高点 0.05% 以内的日子算作在高点，因为这样的回落显示出来是 0.0%。从未进一步回落时，`max` 为 0，也没有日期。
- `current` 是最后一个记录日比到那时为止的最高点低多少；`currentPeak` 是那个高点的日期，只在低于高点时给出。
- 基准的回撤（`benchmark.drawdown`，以及图中的虚线）按同样的方法、用基准在相同日子里的收益计算。
- 它只看得到 TradePilot 记录了账户市值的那些天，所以两个记录日之间发生的下跌和回升不会体现在里面。

<a id="monthly-returns"></a>
## 月度收益

“收益”标签页的**月度收益**表格，以及 `get_portfolio_performance` 里的 `timeWeighted.months` 和 `timeWeighted.years`，给出记录日涉及的每个自然月和自然年的时间加权收益（按 UTC 日期）。至少两个月有收益、且其中一个是完整月份时才显示表格，所以 1 个月窗口不显示：它那两个不完整的月份不比收益图多说什么。

- 一个月的收益从该月之前的最后一个记录日算到该月最后一个记录日，像时间加权收益一样链式计算，所以入金和出金不计入。某个月没有任何记录日时，这个月为空，下个月从它之前的最后一个记录日算起（`from` 会注明）。
- 只记录了一部分的月份为**不完整**（`partial`）：记录从月中开始，或最后一个记录日在月底之前或就是今天（本月结束之前的本月）。
- 从上个月月底之前的某个记录日算起、中间没有读数（服务器没在运行）的月份为**延伸**（`extended`）：它的收益也包含那些天，`from` 注明从哪天开始。文字里会给出它的起止日期。
- 表格里不完整或延伸的月份用虚线框、数值用斜体，悬停文字里有它的起止日期。第一个只有一个记录日的月份没有收益，不显示；之后那个月就成为延伸月份。
- 每行是一年，最近的年份在上，行末是该年自己的收益。格子盈利为绿色、亏损为红色，与持仓热力图一样：达到色阶上限即为最深颜色（上限取 2%、5%、10% 或 20% 中能涵盖五分之四月份的最小值），每格写出数值。窄屏上每年显示为每行四个月的网格。

<a id="investment-goal"></a>
## 投资目标

“收益”标签页的**投资目标**面板和 `manage_goal` 把账户和“在某个日期前达到某个金额”的目标相比较。点**设定目标**会打开表单：目标金额、截止月份（目标日期取该月最后一天，最远 50 年）、每月投入、假设的年化收益（默认 6%，范围 -50% 到 30%）、假设的年化波动（默认 15%，最高 100%）和假设的年通胀（新目标默认 2%，最高 20%；2.94 之前保存的目标按 0 计）。边填表单边重画范围，保存后每个账户在 TradePilot 的存储里保留一个目标。每月投入、收益、波动和通胀的输入框下面各有一个组件自己画的滑杆：可以拖动，也可以选中后用方向键调整（Page Up / Page Down 一次走十步，Home / End 到两端）。拖动时范围跟着重画；要输入精确数字或超出滑杆范围的数（收益 -5% 到 15%、波动 0% 到 40%、通胀 0% 到 10%），仍然用输入框。**用我的账户数据**会填入账户自己在本页所选区间的时间加权收益的年化值和波动率，需要至少一年的市值记录；这是过去的数字，不是预测。修改已保存的目标时，保存之前会显示**已改动，未保存**。

- **进度**是当前市值相对目标金额的比例。
- 年通胀大于 0 时，一切都按今天的购买力计：目标金额、每月投入（随物价上涨）以及预测；预测按扣除通胀后的收益增长，即 (1 + 收益) / (1 + 通胀) − 1。
- **进度快慢**：保存目标时会记下当时的账户市值作为起点，直到目标金额改变。满一个月后，面板会说明现在的市值比“从起点按中间线、每月投入”应到的位置多还是少（`manage_goal` 的 `projection.pace`）。假设了通胀时，中间线会换算成今天的金额，所以账户按假设的收益率增长就算正好按计划。落后也可能是投入比计划少，不一定是市场不好。
- 范围不是预测。增长按对数正态分布计算：每年对数增长的中位数是 ln(1 + 收益) 减去方差的一半，**偏低**和**偏高**两条线是各个期限上它的第 10 和第 90 百分位（两侧各偏离波动率 ÷ √年数），所以 10 种结果里有 8 种落在两条线之间：期限越长，年化增长的区间越窄，但金额的区间越宽。每月的投入从当月月底起按同样的速度增长。图上每月一个点，十年以上每季度一个点；只算投入、不算增长的金额画成虚线，目标金额横贯全图。
- **达成概率**是在同样的假设下，整个期限的年化增长不低于刚好达到目标所需增长的概率。账户已经达到目标时显示为已达成。
- **按中间线需每月投入**是要让中间线在截止日期前达到目标，每月需要投入多少。
- 仪表盘在账户市值下面显示目标：名称、完成比例和一条短进度条，点一下打开“收益”标签页的目标。
- 市值第一次达到目标的 25%、50%、75% 和 100% 时，调度器会通知（[AUTOMATION.md](./AUTOMATION.md#goal-milestones)）；周报和月报也会写出目标进度。
- 不计费用、税和投入金额的变化；年通胀设为 0 时也不计通胀。组件和服务器用同一套计算（`src/shared/goal.ts`），`get_portfolio_performance` 会以 `goal` 返回已保存的目标。

<a id="risk"></a>
## 风险

“收益”标签页的**风险**面板，以及 `get_portfolio_performance` 里的 `timeWeighted.risk` 和 `benchmark.risk`，说明时间加权收益每天的涨跌幅度有多大。有 20 段读数间隔后才显示。因为按时间加权收益计算，入金和出金不算涨跌；账户空着的日子（清空后又重新入金）算作没有涨跌的日子。

- 市场在工作日交易，所以每段读数间隔按它覆盖的工作日数计算。周末的读数会把它所在的那段并入下一段，所以周末的变动（现金利息、汇率）和周一算在一起；周五没有读数时，周末读到的那段算作周五的。今天的最后一次读数可能在收盘之前，所以截止到今天的那段在当天结束前不计入任何指标。
- **年化波动率**是每个工作日涨跌（取对数）的标准差乘以 √261（一年的工作日数）。相隔几个工作日的一段读数（服务器没在运行）按相应的工作日数计：它的涨跌的方差除以它的长度。假日算作没有涨跌的工作日，和 261 的口径一致。
- **收益 ÷ 波动**是按这段时间的速度折算的年收益除以波动率，不扣除无风险利率。它需要一年的读数（和年化资金加权收益一样），以及每年 0.5% 及以上的波动率：和现金差不多的账户会稳定上涨，它的收益除以波动率说明不了什么。
- 相对基准的 **Beta** 表示基准每涨跌 1% 时收益涨跌多少；**相关系数**在 -1 到 1 之间，表示两者同涨同跌的程度；两者都按双方都有的那些间隔计算。它们需要 60 段间隔（因为比波动率的噪声更大），以及基准每年波动 0.5% 及以上（货币市场基金的 Beta 会是几百量级的噪声）；在此之前只显示基准的波动率。每天的读数可能在任何时间记下，常常在基准收盘之前，这时它包含了基准前一天的一部分走势：如果只和同一天比，一个与基准完全相同的组合在上午读数时 Beta 会接近 0。所以每段间隔会同时对基准的前一段、同一段和后一段做拟合，Beta 是三者之和（Dimson Beta）。相关系数是这个 Beta 乘以基准与收益的离散程度之比，二者各自按多天计算（方差加上两倍的与前一天的协方差），这样延续到第二天的涨跌只算一次。基准按其自身货币计价，所以其货币相对账户货币的涨跌也包含在内。
- **单日最大涨幅**和**单日最大跌幅**、**上涨天数**，以及**每日涨跌分布**图只统计单个工作日的间隔，而且只统计涨跌达到 0.005% 及以上的，所以假日不会出现在其中任何一项里。图中每根柱的宽度为 0.25%、0.5%、1%、2%、5% 或 10%，取能让柱数不超过 16 根的最窄宽度，而且柱子不会跨越 0；即使用最宽的宽度也超过 16 根时，最后一根包含所有更大的涨幅。

<a id="risk-by-holding"></a>
## 持仓风险分布

“配置”标签页的**持仓风险分布**面板，以及 `analyze_portfolio_allocation` 里的 `risk`，说明持仓的风险集中在哪里：每个持仓在组合波动中所占的份额，与它在市值中所占的份额并列。风险占比大于市值占比的持仓，要么比其他持仓波动更大，要么和它们更同步。

- 它从行情源读取每个持仓最近一年的日收盘价（与持仓页共用同一份缓存），从最大的持仓开始，每次四个，最多等五秒。到时还没读到的持仓会被列出（`riskMissing`，原因为 `later`）：它们会在后台继续读取，所以稍后点**刷新**（或再次调用该工具）就会从缓存中计入。行情源没有收盘价的持仓会列出并注明原因；行情源对所有持仓都不提供收盘价时（`QUOTE_PROVIDER=none`，或 Finnhub 的免费套餐），只说明一次。
- Alpha Vantage 的免费套餐只能回溯约 100 个交易日，周数太少，所以根本不会向它请求这些收盘价：它每天 25 次的请求额度留给仪表盘、提醒和图表。Stooq（默认）和 Twelve Data 都能回溯一年。
- 收盘价按周取：每周（周一到周日）的最后一个收盘价，本周要等结束后才计入。周收益能让收盘时间不同、假日不同的市场保持同步，日收益做不到（伦敦比纽约早几个小时收盘）。每个持仓用自己的币种，所以不含汇率变动。完全没有收盘价的一周（市场整周休市）并入下一周，其收益按相应的周数计入方差。
- 持仓需要超过 26 个周收益，且周收盘价个数至少达到收盘价最多的那个持仓的四分之三，才会被测算：下半年才买入的持仓会被排除，而不是缩短其他所有持仓的计算周数。已测算的持仓按它们都有的那些周计算，这些周也必须给出超过 26 个周收益；它们对不齐时（某个持仓有空缺，另一个收盘价中断），每次排除一个持仓，排除的是去掉之后共有周数最多的那个，直到够数为止。`short` 列出因这两种原因被排除的持仓。收盘价在相邻两周之间涨到五倍以上或跌到五分之一以下的持仓作为 `jumps` 排除：这是计价单位变了（英镑换成便士）或拆股，不是真实涨跌。
- 已测算的持仓按现在的市值在彼此之间加权；`covered` 是它们占全部持仓市值的比例。
- **组合波动率**是加权后持仓周对数收益的标准差乘以 √52。持仓的**风险占比**是它的权重乘以它与整体的协方差，再除以整体的方差：各持仓的风险占比加起来是 100%，对冲其他持仓的那只风险占比小于 0，画成斜纹条，长度按它的大小。**与整体的相关系数**是这个协方差除以它自身的波动率和整体的波动率。
- **分散度**是各持仓自身波动率的加权和除以组合波动率：全部同步时为 1，相互抵消越多数值越高。
- **相互之间的联动**是最大的十个持仓两两之间周收益的相关系数，在 −1 到 1 之间：琥珀色表示同向，蓝色表示反向，0 为面板自身的颜色，每格写出数值，悬停文字里有两个名称。
- 它需要两个及以上持仓，以及一个行情源；样例账户使用样例收盘价，这些收盘价共享一个市场因子，所以持仓会同向变动，但不完全同步。

<a id="todays-mix-over-the-year"></a>
### 当前持仓回看一年

在它下方，**当前持仓回看一年**，以及 `analyze_portfolio_allocation` 里的 `risk.mix`，说明如果这些已测算的持仓在同样这些周里一直按今天的权重持有、每周调回这些权重，会是什么表现。每周收益是它们从一个周收盘价到下一个的加权变动，各用自己的币种，所以不含汇率变动、费用和税，分红只在行情源的收盘价包含时计入。某个持仓没有收盘价的那一周（该市场整周休市，或行情源的收盘价有空缺）并入下一周：这段会画进曲线、计入收益，但不算作一周，所以糟糕周、最差和最好一周以及上涨周数都只统计单周。

- 曲线是组合在每个周收盘时所处的位置，从第一个周收盘的 0 开始；表格视图会列出数值。
- **收益**是它在这些周里的收益，并给出上涨的周数。
- **20 周一遇的糟糕周**是组合在最差 5% 的周里跌到或跌破的周收益：n 个周收益里倒数第 ⌈n/20⌉ 个（52 周里倒数第 3 个），即历史 95% VaR。它也按账户币种给出金额，以已测算持仓今天的市值为基础（不含现金，也不含被排除的持仓），并给出这些最差周的平均值（预期短缺，expected shortfall）。它说明糟糕的一周大概什么样，不是持仓最多可能亏多少。连那一周都是上涨时（组合下跌的周数少于二十分之一），就没有这个数字：卡片显示**没有下跌**。
- **最差一周**和最好一周按该周最后一个收盘日标注日期；**最大回撤**是组合距高点的最大跌幅（同上文的回撤），以及何时回本。

<a id="against-the-market"></a>
### 对大盘的敏感度

在它下方，**对大盘的敏感度**，以及 `analyze_portfolio_allocation` 里的 `risk.market`，说明已测算的持仓如何随基准变动（`BENCHMARK`：默认是通过 SPY 跟踪的标普 500；样例账户使用它自己的标普 500 基金）。它按持仓的那些周里基准也有收盘价的周计算，用周对数收益，各用自己的币种，需要超过 26 个。

- **贝塔**是持仓与基准的协方差除以基准的方差：1 表示与大盘同步，1.5 表示多波动一半，0 表示不跟随，小于 0 表示反向。持仓整体的贝塔是各自权重乘以各自贝塔之和；卡片给出它，以及它们与基准的相关系数。每个持仓是一根从 0 出发的条，在 1 处有虚线标记，从高到低排列，旁边是它在已测算市值中的占比；表格视图还会加上它的相关系数。
- **基准的波动率**：这些周折算的年化波动率；以及它在这些周里**最差的一周**，按它自己的收盘价计算、以该周最后一个收盘日标注日期，并在每个持仓那周都有收盘价时，给出当前持仓那一周的表现。
- **如果基准下跌** 5%、10% 和 20%，已测算的持仓会变动它们的贝塔乘以该跌幅，按账户币种以它们现在的市值给出金额，并给出占账户（含现金）的比例，现金和未测算的持仓按不变动计。这个数字只来自贝塔：每个持仓还有自身的波动，所以实际下跌时可能更多或更少。这是过去一年的平均，不是预测。

基准在持仓之后读取，同在那几秒之内；基准本身是持仓之一时不会重复读取。读不到它的收盘价时，这个面板不显示，其余的风险分析照常显示。

<a id="equal-risk-weights"></a>
### 风险平价权重

再往下，**风险平价权重**，以及 `risk.rows` 里每一行的 `parity`，给出让每个已测算持仓贡献相同风险份额的权重（等风险贡献，即风险平价），基于同样这些周。波动大或与其他持仓同步的持仓权重更低；平稳的，或能对冲其他持仓的，权重更高。它们是已测算持仓之内的占比，和旁边的 `weight` 一样；`risk.parityVolatility` 是按这些权重、用同样这些周算出的组合波动率。

- 它们是让每个持仓的 x_i(Σx)_i 都相等的权重 x，逐个持仓求解（对 ½x'Σx − Σ ln x_i / n 做循环坐标下降），再缩放到总和为 1。只有两个持仓，或持仓之间互不相关时，权重与各持仓的波动率成反比。
- 求解所用的协方差矩阵会向一个“每对持仓都取平均相关系数”的矩阵收缩，收缩程度取决于这些周的数据对每对持仓自身的相关系数有多不确定（Ledoit 和 Wolf 的常相关收缩）。持仓多、只有 52 周时，样本对某一对持仓的说法很多是噪声，只按样本求解的权重会追着噪声走；每个持仓自身的波动率保持不变。只有会波动的持仓才一起收缩，所以一个平稳的持仓既不会妨碍收缩，也不会拉低平均相关系数。这些权重下的波动率按样本计算，和今天的一样。
- 年化波动不到 2% 的持仓（现金、货币市场基金）保持原权重，其他持仓分配剩下的部分：如果把它一起算进去，它会占去组合的大部分，因为需要很多它才能带来和一只股票一样多的风险。
- 年化波动达到 2% 及以上的持仓少于两个，或者没有任何权重能让持仓的风险占比相等（完美对冲，组合没有风险可分）时，就没有这些权重，面板也不显示。
- 卡片给出按这些权重的合计波动和今天的对比、调到这些权重需要卖出（再买回）的金额（按账户币种；提供调仓草稿时，是草稿要卖出的金额），以及偏离风险平价权重最大的持仓。每个持仓画成一根哑铃：圆环是今天的权重，圆点是风险平价权重，按偏离从大到小排列；表格视图列出全部持仓及其变化（百分点）。
- 有下单工具时，**生成调仓草稿**会调用 `plan_portfolio_rebalance`，目标是把已测算的持仓调到这些权重，同时保持它们的合计市值不变：每个目标 = 它的风险平价权重 × 它们的合计市值 ÷ 账户市值。未测算的持仓不设目标、保持不变，现金权重为可交易的现金，所以用卖出的钱支付买入。一个订单篮最多 20 笔订单，所以已测算的持仓更多时，只调整偏离风险平价权重最大的 20 个（保持它们的合计市值不变），其余不动。目标按读到的市值计算，所以价格大幅变动后请先点**刷新**。它会作为订单篮打开，供你检查；确认之前不会发送任何订单。工具的文字也会给出同样的目标，供助手据此制定计划。
- **设为目标**会打开 [目标权重](./AUTOMATION.md#saved-targets-and-drift-notices) 表单并填入这些权重（按占整个账户的比例，未测算的持仓和现金按今天的比例），保存后会跟踪它们的偏离并发送提醒。
- 在这个表单里，以及已保存的目标旁边，会用同样这些周算出这组目标下的波动率，与今天的对比（参见 [已保存的目标](./AUTOMATION.md#saved-targets-and-drift-notices)）。没有持有的目标标的，只要在这些周里每周都有收盘价、且没有跳变，也会用它自己的收盘价按这些周计算；它不影响持仓的风险。

这些权重按持仓过去一年的波动来分散风险。它们不代表持仓未来的收益，过去平稳的持仓也可能不再平稳。

<a id="price-and-exchange-rate"></a>
## 价格与汇率

以其他币种报价的持仓会有两重盈亏：价格的涨跌，以及买入以来汇率的变动。Trading 212 用 `walletImpact.fxImpact` 给出后者，即持仓未实现盈亏中由汇率带来的那部分，按账户币种计。在未实现盈亏下方，总览和持仓页把它拆成**价格**（盈亏减去汇率部分）和**汇率**两部分，各画成一根从零出发的条，按两者中较大的那个缩放；持仓列表在每个持仓的盈亏下方给出它的汇率部分（“汇率 -€60.62”）。仪表盘的文字给出同样的内容，`analyze_portfolio_allocation` 也会返回每个持仓的 `fxImpact`。

- 以账户币种计价的标的（包括英镑账户里的便士）没有汇率部分。没有 `fxImpact` 的外币持仓不拆分；只要有任何持仓缺少汇率部分或盈亏，总览也不拆分，所以两部分加起来总是等于显示的盈亏。文字里会数出有多少个持仓以账户以外的币种计价。
- 总览的价格部分 = 账户的未实现盈亏 − 各持仓的汇率部分。
- 汇率对结果的影响不到一分钱时，不显示拆分，也不显示汇率部分。

<a id="your-position"></a>
## 持仓走势

持仓页的**持仓走势**图画出持仓在每个日收盘时的市值，旁边是一条“净投入”虚线：第一个收盘日所持的股数按当天收盘价计，加上此后每笔买入的花费，减去每笔卖出的所得，都按成交价计算。两条线之间的差距就是价格为这笔持仓带来的盈亏，不受买卖影响；`get_holding_detail` 的文字也会给出同样的内容。卖出所得超过投入时，净投入会低于零，这时坐标轴会显示零。

- Trading 212 只报告今天的股数，所以每天的股数 = 今天的股数 − 那天之后的买入 + 那天之后的卖出，依据页面读取的一年成交（两页，每页 50 个订单）。第一个收盘日当天的成交计入期初股数。成交按其 UTC 日期的收盘计入，所以收盘后的成交在图上会提前一天出现；最终的盈亏不变。
- 没有读到更早的成交时，图表从读到的最早一笔成交那天开始（因为那之后的每笔成交都已知），并会注明。
- 金额按今天的汇率换算为账户币种：用 Trading 212 自己对这个持仓的估值所隐含的汇率；已全部卖出的，用同币种另一个持仓的。都没有时，用它成交时的汇率，并在说明里注明。
- 以下情况不显示图表，页面会说明原因：倒推成交时某一天的股数少于零（股份不经成交就转出）；收盘价一天内涨到 1.8 倍及以上（或跌到 0.55 倍及以下），或者某笔成交价是当天收盘价的 1.4 倍及以上（或 0.7 倍及以下），像拆股前后那样；某笔成交是派发或其他公司行动而不是交易，或是看不出比例的拆股；或者某笔成交缺少价格或日期。Trading 212 在成交里列出的拆股或合股（`STOCK_SPLIT`）只是同一笔持仓换了单位：它自己的成交不计入，之前的成交按拆股后的口径计算（股数乘以比例，价格除以比例）。收盘价没有按拆股调整时（当天按比例跳变），拆股日之前的收盘价会除以比例，所以两种收盘价都能画图。收盘价已调整时，价格图把拆股前的成交按拆股后的价格标出，标签里会注明。比例来自拆股关闭和新开的股数；如果只列出新增的股数，就用现在的持仓，倒推拆股之后的成交得出。不经成交转入的股份（转入、赠股）从第一个收盘日起算作持有。

<a id="the-days-move"></a>
## 当日涨跌

Trading 212 的 API 给出每个持仓的现价，但既不提供前一收盘价，也不提供当日涨跌，所以 `get_portfolio_today`（以及刚加载完的仪表盘）会从行情源的日收盘价里取前一收盘价，也就是持仓页图表画的那些收盘价。

- **当日**是 Trading 212 的价格所属的交易日，依据交易所时间表（`metadata/exchanges`）：正在进行的交易时段；对于 Trading 212 支持延长时段交易的标的（`extendedHours`），在盘前或夜盘时段，是接下来开盘的那一天；其他情况是上一个交易日。所以开盘前、夜间和周末显示的是上个交易日的涨跌，仪表盘会注明是哪一天（“上个交易日（10月9日周五）的涨跌”）。没有时间表时，就是今天；周末则是之前的周五（UTC）。
- **前一收盘价**是行情源在那一天之前的最后一个收盘价。在上个交易日收盘后 6 小时内，如果收盘价还没到那一天，说明行情源还没发布：该持仓不显示涨跌（`missing: "lag"`），而不是显示两天的涨跌。过了这个时间，就按行情源现有的最后一个收盘价计算，因为交易不活跃的标的可能会缺一天；它的日期在 `previousClose` 里，也在仪表盘的悬停文字里。
- **涨跌**是现价对比那个收盘价，按标的自身的币种和单位计。
- **盈亏**：前一收盘时持有的股数从收盘价算起，当天买入的从成交价算起，当天卖出的算到成交价为止，所以今天才买入的持仓只显示买入之后的表现。当天的成交是指该标的所在交易所上一交易日收盘之后的成交（盘后交易计入下一天），没有时间表时则是当天零点（UTC）之后的成交；与收盘价相差一百倍的成交价（便士对英镑）会换算到同一单位。当天全部卖出的标的仍会计入它的卖出。盈亏按今天的汇率换算，汇率由 Trading 212 对持仓的估值推算，所以不含当天的汇率变动。订单历史读取最新的 100 个订单：3 秒内没有返回，或者当天的订单超过这个数时，`fillsProblem` 会注明，缺少成交记录的股数从前一收盘价算起。
- **合计**把有涨跌数据的持仓加起来；它的 `change` 是相对于这些持仓在前一收盘时的市值加上当天买入金额计算的。`counted` 和 `of` 说明有多少个持仓有涨跌数据。

标的页（`get_holding_detail`）以 `day` 给出该标的同样的当日涨跌，用的是它的图表读取的收盘价，成交来自页面的订单历史；未持有的标的只给出报价本身的涨跌。每日摘要开头就是合计，以及涨跌最大的三个持仓。

收盘价按标的缓存半小时，与持仓页和自选列表共用；不会再变的前一收盘价（上个交易日的，或者收盘已过 6 小时的任何收盘价）会保留到当天结束，所以之后刷新时不会再为它请求行情源。读取时每次向行情源请求四个持仓，5 秒后不再发起新的请求；其余持仓在下次刷新时得到涨跌（`missing: "later"`）。它最多等待 3 秒获取 Trading 212 的标的列表和时间表。仪表盘显示出来之后才读取当日涨跌，所以慢的行情源不会拖慢它，而且只针对最近 2 分钟内读取的仪表盘（不针对再次显示的已保存结果）；读取失败时，仪表盘会给出说明，不显示这一列。读取会复用仪表盘在最近 15 秒内对账户的读取，或加入正在进行的那次读取，而不会再次请求 Trading 212。

<a id="periods"></a>
## 时间区间

历史类工具接受 `period`（`1w`、`1m`、`3m`、`ytd`、`1y`、`all`），或用 ISO 8601 格式明确指定 `from` 和 `to`。`get_tax_year_summary` 则使用 `year` 和 `yearStart`。

它们从最新的记录开始读取历史，每页 50 条。Trading 212 按分钟、按接口限制历史读取次数，所以每个工具对每类数据最多读取 `maxPages` 页（默认 10 页，最多 40 页）。每个请求都按 Trading 212 在响应中报告的限额控制节奏（参见 [调用限速](../../README.zh-CN.md#调用限速)）；如果为此需要等待超过一分钟，读取会带着已读到的内容返回，并标记为已截断。

在覆盖所请求的期间之前额度就用完时，结果会标记为 `truncated`。这时会省略简单收益率和年化收益率，因为它们会是错的。

<a id="the-history-ledger"></a>
### 历史记录账本

Trading 212 历史里的记录是最终的（已成交或已撤销的订单、已派发的股息、已结算的资金变动），所以 TradePilot 会保存读到的记录，按账户（以 API Key 的单向摘要命名，绝不保存 Key 本身）和按类型分开保存。回溯超过 60 天的读取会用到它（收益、税务年度、收入、日志、全部历史的交易记录）；更短的读取直接请求 Trading 212，只需要一两页。样例账户不保存：它的历史是相对今天生成的。本地服务器把它存在 `state.json` 旁边的 `ledger.json` 里；在 Cloudflare 上，存在 Worker 的 Durable Object 里，每个值不到一百万个字符。

已知的部分以“段”保存：每段是一次连续读取、中间没有空缺的一段历史，从读取开始时的最新记录一直到读到的最旧记录。一次读取从最新记录开始一段，向下读，直到接上下面那一段。它会越过那一段的起点再多读三天，因为资金变动可能稍晚才结算，在读取前刚下的订单也可能在读取后才成交。然后用剩下的 `maxPages` 从最新一段的终点继续往更早读，最远到期间的开始。所以长期间的 `truncated` 结果并不是终点：再请求一次会从那里继续（被截断的结果不会缓存）；一旦读到账户的第一条记录，之后每次读取只需读上次读取以来的页面，外加它之前的三天。新记录多到一次读取读不完时，最新的记录会单独保存为一段，并单独返回、标记为已截断，而不是在它们和更早的记录之间留一个空洞；下一次读取会把它们接上。

Trading 212 在历史里按订单的创建时间排列，所以几周前下、今天才成交的订单会落在旧记录中间。每次读取订单都会先读取仍未成交的订单，并记下它们的 id；一旦某个订单不再处于未成交状态，就到它所属标的的历史中找它，一直找到它的创建时间。找到之前，结果都标记为已截断；Trading 212 尚未列出的订单会在两天内反复查找，之后放弃。读取某个标的的历史时，只计入该标的的订单。读不到未成交订单时，读取会直接请求 Trading 212，不保存任何内容。

记录按集合保存：每次读取把新发现的记录作为单独的块加入，读取时取所有块的并集，每条记录只算一次。不会就地改写任何内容，所以一次定时任务和一个请求、或者共用一个文件的两个本地宿主同时写入时，不会丢失对方的记录；超过 24 个块后，下一次读取会把它们合并。每类记录最多保存 25,000 条（`HISTORY_MAX_RECORDS`；设为 `0` 则全部保存，但在 Cloudflare 上，账本超过约 30 MB、大约 4 万笔订单时，Durable Object 一次读取交不回来，历史就会每次都直接从 Trading 212 读取）；超出后删除创建最早的记录，直到剩下上限的十分之九（之后才成交的旧订单会保留），回溯到它们之前的期间会标记为已截断。交易频繁的账户留下的、没能接上的段（新记录比一次读取的 `maxPages` 能读到的还多）最多保存八段，最旧的最后删除。Trading 212 拒绝继续往前读（游标过期）时，这一段会被遗忘，之后的读取会越过它向下读；它的记录仍会保留。读取中途失败（触发限速、服务器错误、之前读到过记录的地方返回空结果）时，读取会带着已有内容停止，标记为已截断；状态存储失败只影响账本，不影响读取：读取会直接请求 Trading 212。单个标的的历史（持仓页）在最新一段回溯到期间开始之后从账本获取；在此之前，使用 Trading 212 自己的 `ticker` 筛选。每个服务器进程对同一账户同一类型的读取依次进行，所以两次同时读取不会把相同的页面读两遍。

<a id="how-the-figures-are-defined"></a>
## 指标定义

- **金额**按账户币种计，与 Trading 212 报告的一致。
- **已实现盈亏**是 `fill.walletImpact.realisedProfitLoss` 之和，已经反映了成交时的汇率。
- **费用**是每笔成交附带的税费（佣金、货币兑换费、印花税、FINRA 费用等），加上 `FEE` 类型的流水。
- **简单收益率**是 `(current value − net contributions) / net contributions`。它不是时间加权的，也没有年化。两种收益率都和当前账户市值比较，所以 `to` 在过去的窗口两种都没有。
- **时间加权收益**（`timeWeighted`）衡量的是投资本身，而不是投入的钱：它剔除了入金和出金，所以是用来和指数或基金比较的那个数字。它根据 TradePilot 的每日市值记录（见下文）计算，所以覆盖窗口内的记录日，适用于任何期间，包括已经结束的期间。两个记录日之间的每一段用 Modified Dietz 方法计算：`(end value − start value − flows) / (start value + Σ flow × share of the stretch it was in)`，各段再链式相乘，`(1 + r₁)(1 + r₂)… − 1`。空账户不产生收益，所以从空账户开始的一段从第一笔入金算起，以空账户结束的一段算到最后一笔出金为止（账户市值低于 1，或低于该段资金进出总额的 1%，即视为空账户）：否则在读数前一小时向空账户入金，会把那一小时的收益当成一天的收益。入金、出金和 Trading 212 账户之间的转账来自交易流水，按发生时间放入。`series` 给出每个记录日的链式收益，`netFlows` 是它剔除掉的投入减取出的金额。交易流水的读取在第一个记录日之后就停止时（调高 `maxPages`），以及某一段开始时还没有任何投资、市值却变了时，不给出该指标。服务器没在运行的日子会合并成一个更长的段，其中的入金只按时间加权，相当于假设市值在这段空缺里均匀变化；记录的天数越多，结果越接近精确的时间加权收益。
- **基准**（`benchmark`）是指数基金在时间加权收益那些天里的价格收益：它在每个记录日当天或之前的收盘价，对比在第一个记录日当天或之前的收盘价，所以周末或假日取之前最后一个收盘价。默认是通过 SPY 跟踪的标普 500（美国代码在每个行情源都能对应上），服务器上的 `BENCHMARK` 可以更改它（Trading 212 的 ticker、代码或名称，或美国代码；`none` 表示关闭），调用时的 `benchmark` 或“收益”标签页上的**对比**可以为这次读取另选一个，可选项包括默认基准、持有的 ETF 和自选列表里的 ETF（`benchmarkOptions`）；`benchmarkChoice` 是实际使用的那个。Trading 212 在多个交易所上市的代码（例如 VWRL）会返回 `benchmarkMissing: "instrument"`，各上市地列在 `benchmarkProblem` 里：请用准确的 ticker 选择（`VWRLl_EQ`）。Trading 212 没有上架的美国代码（SPY、QQQ、VT）照样通过行情源对比。收盘价至少回溯一年读取，所以一年以内的期间共用一次缓存读取。它按基金自身的币种计价，所以对于其他币种的账户，差距中有一部分来自汇率；派息型基金的价格不含分红，累积型基金的价格则包含分红：要做同口径对比，请选择以账户币种计价的累积型基金，比如在 `QUOTE_SYMBOLS` 中映射的 `EUNL`（iShares Core MSCI World，EUR）。行情源没有它的收盘价，或收盘价回溯不到第一个记录日之前一周以内时，`benchmarkMissing` 和 `benchmarkProblem` 会说明原因。
- **年化收益率**是资金加权收益率（XIRR）：让每笔入金、每笔出金和今天的账户市值净额为零的年化利率。它考虑资金投入的时间，所以上个月的入金比三年前的入金权重小。它在截止到现在的全部历史窗口、且第一笔入金满一年后给出，历史被截断时省略。
- **税务年度**数字使用 Trading 212 每笔卖出的已实现盈亏，按你的平均买入价、以卖出时的汇率计算。税法有自己的买卖匹配规则（例如英国的同日规则和 30 天规则），股息是扣除源头预扣税后的金额。卖出按成交时间计入成交所在的年度；缺少 Trading 212 账户币种金额的卖出不计入卖出所得，并在备注中列出。请用这份汇总来准备和核对申报；正式申报请以 Trading 212 年度对账单或 CSV 导出（`manage_history_export`）为准。
- **英国匹配规则（估算）。** 英国税务年度（从 `04-06` 开始）的汇总还会返回 `ukMatching`，按 HMRC 的方式重新匹配同样的卖出。每笔卖出先匹配同一标的在英国时间同一天买入的股份，再匹配之后 30 天内买入的股份（先买的先配，先卖的先配），剩下的按平均成本从此前全部买入组成的第 104 条资产池里扣除。无论汇总其余部分用哪个 `timeZone`，这里的日子和年度都按英国时间（Europe/London 的 4 月 6 日到次年 4 月 5 日）计算；同一家公司在两个代码下上市时算作一个资产池，Trading 212 给出 ISIN 时按 ISIN 归并。收益和亏损按每次处置（同一标的在英国时间同一天的全部卖出）分开累计，与申报时的加总方式一致。结果按标的给出收益、每条规则匹配的股数，以及 Trading 212 对同样卖出的数字。英国年度通过账本只读取一次全部历史，并从中取出本年度的卖出；随后把每个标的的成交加总，与现在的持仓核对。拆股或合股按 HMRC 的处理（TCGA 1992 第 127 条）视为同一笔持仓换了单位：之前买入和卖出的股数按拆股后的口径计算，成本不变，所以拆股前卖出、拆股后买回会按相同单位匹配；每个标的会列出 `splits`，包括英国时间的日期和比例。看不出比例的拆股（只列出新增股数，而且既没有持仓也没有之前的成交可以推算）保持原样。成交加总与持仓不符的标的说明有股份通过其他方式进出（转入转出），会标出两个数字；含有非交易成交（派发、合并）的标的也会标出。金额是 Trading 212 在账户币种下每笔成交的净值，视为已含手续费和换汇费；账户币种不是英镑时会注明需要换算。无法匹配或估值的股份会被计数，但不计入收益；出现以上任何一种情况，结果都会标为不完整，此时不再与 Trading 212 的数字比较，因为后者包含英国规则这边漏掉的卖出。年度结束后 30 天内，最后几笔卖出还可能与之后的买入匹配，结果会注明（`provisional`）。股票与股份 ISA 账户里的收益免税。税年页会把它和 Trading 212 的数字并排显示。
- **股息收益率和未投资的现金。** 周期截至现在时，“收入”标签页和 `get_income_summary`（`yields`）取每个持仓近 12 个月的每股股息，按现在持有的股数计（`trailing`；`paid` 是实际收到的现金），分别除以 Trading 212 记录的该持仓总成本（成本股息率）和当前市值，并用未来 12 个月的预计股息除以成本；按持仓列出已付或预计会付股息的标的，成本股息率高的在前。只用 Trading 212 给出的账户货币成本和市值：缺少其中一项的持仓会让账户的那项收益率不给出；成本为 0 的持仓自己没有成本股息率，但在账户合计里按 0 计。已卖出标的的股息不计入。`cash` 给出未投资的现金（`total`：可交易、投资组合中和为挂单预留的合计）、占账户市值的比例、近 12 个月的现金利息（股票借出收入另列），以及 `rate`：从 TradePilot 这一年里第一个记录日起的现金利息，换算成年利率，分母是记录日可交易现金的平均值。至少需要 30 天、其中五分之四有记录；不够时为 null，因为只用今天的余额可能算出几千个百分点。周期截至现在指：没有截止日、截止时间在请求前五分钟以内，或截止日是一个日期且在 12 小时内刚结束（UTC 以西读者的今天）；这在读取请求时就确定，历史读取慢也不会改变。周期在更早时候结束时两者都不给出，标签页会说明原因。
- **账户市值历史**是 TradePilot 自己的记录，因为 Trading 212 的 API 只报告今天的市值。服务器运行期间，调度器大约每小时读取一次账户摘要，保留每个 UTC 日的最后一个值，以及可交易现金和持仓市值（`src/core/value-history.ts`）。每个值按 Trading 212 返回的时间标注日期，所以跨过 UTC 午夜的读取算作新的一天。服务器没在运行的日子没有数据点，图表按日期排布数据点，所以空缺会保持可见。数据点保存约六年，每月一个存储键。样例账户有自己的记录；切换到另一个 Trading 212 账户后，只显示当前账户的日子（账户 id 保存在存储中）。有两天及以上数据时，`get_portfolio_performance` 以 `valueHistory` 返回窗口内的日子（日期边界按整天比较，日期时间边界按每个值的读取时间比较），“收益”标签页把它们画成一条线，带悬停读数和表格视图。`get_portfolio_dashboard` 以 `valueTrend` 返回所显示账户最近 30 天的数据，仪表盘把它们画成总市值旁边的一条小折线，并给出自其中第一天以来的变化。市值包含入金和出金，所以不是收益率。
- **集中度**只按投资市值计算，所以大笔现金余额不会掩盖组合的集中。提示阈值可以在每次调用时覆盖。

## 交易时段提示

下单审核使用同样的交易所时间表。休市时，确认界面会显示提示。

对于不在可用延长时段内的市价单，提示会说明 Trading 212 会将订单排队，在下次开盘时成交，成交价可能跳空。

<a id="limits"></a>
## 限制

Trading 212 的 Public API 没有报价接口。只有已经持有的标的才能通过持仓接口拿到现价。
