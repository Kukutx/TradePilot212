# 交易日志

简体中文 · [English](../JOURNAL.md)

TradePilot 为每笔交易保存一条记录：当时为什么做，以及事后回头看结果如何。记录保存在 TradePilot 自己的存储里（和价格提醒、定投计划用的是同一个），从不发送给 Trading 212。

<a id="writing-a-note"></a>
## 写记录

- **随订单一起写。** 订单编辑器里有 **交易理由** 字段，`review_trading212_order_intent`、`review_trading212_order` 和 `app_prepare_order` 都接受 `thesis`。审查页面会把理由和订单一起显示。Trading 212 接受订单后，理由会存成一条记录，附上 Trading 212 给这笔订单的订单号。结果不明的订单也会保留记录，只是没有订单号，并标为未确认；**检查状态**（`app_verify_unknown_execution`）找到这笔订单后，标记会去掉，如果这样找到的是一笔挂单，记录还会得到它的订单号。记录没能保存时（日志已满，或存储出错），结果里会说明，订单照常有效。在 Demo 和 Live 之间切换时，理由会随草稿一起带过去。从交易计划卡片发出的订单，会以卡片上的核心逻辑或理由作为初始内容，你可以在编辑器里修改或清空。篮子（再平衡、定投计划、组合止损）不带理由。
- **写在过去的成交上。** 在持仓页上，每笔还没有记录的成交都有 **写一条**。这条记录绑定到该成交对应的订单。
- **写在标的上。** 持仓页日志顶部的 **写一条** 可以写一条不关联订单的记录，比如买入前你在等什么。
- **在对话里写。** `manage_trade_journal` 配合 `action: "add"`、一个 `instrument` 以及 `thesis` 或 `review`；再加上来自 `get_trade_history` 或 `get_order_status` 的 `orderId`，就会把它绑定到那笔订单。

每条记录可以有理由（为什么）、复盘（回头看）或两者都有，各最多 1000 个字符，另外最多 8 个标签。一笔订单最多只有一条记录，两次保存同时发生时也一样：再添加第二条时会指出已有的那一条，方便你改它；删除记录后，这笔订单就可以重新写。最多保存 1000 条记录。

<a id="reading-them"></a>
## 查看记录

- 持仓页按从新到旧列出该标的的记录，以及它已列出的成交上的记录，每条都注明对应的成交（方向、数量、价格和交易日期）。每笔有记录的成交下方会显示它的理由。只有理由的记录会提供 **写复盘**。
- `get_trade_history` 返回每笔成交的 `orderId`，并在 `journal` 下返回所列订单上的记录。
- `get_holding_detail` 在 `journal` 下返回该标的的记录：最新的 20 条，以及已列出的成交上的记录；还有更多时附带 `journalTotal`。
- `manage_trade_journal` 配合 `action: "list"` 返回某个环境的记录，可以只看一个标的（即使 Trading 212 已不再列出该标的，记录上带的 ticker 也能匹配）或一笔订单。

<a id="looking-back"></a>
## 复盘

**日志** 标签页，或在对话里用 `get_journal_review`，会把这段时间内已成交订单上的每条记录，和这笔交易此后的走势放在一起对照：

- **顺向幅度**：成交后价格朝交易有利方向走了多少，买入看涨幅，卖出看跌幅。比较的是成交价和现价：持仓用券商的价格，已不持有的标的用行情源的价格。每次复盘最多向行情源查询约 8 个标的，而且逐个查询，因为免费套餐每分钟只允许少量请求，价格提醒也共用这份额度；因此没取到价格的标的会在页面上列出。没有报价的标的，或报价与成交价相差十倍以上（无论高低；最可能是代码映射到了另一个单位，比如以便士报价的基金被当成英镑），都不计顺向幅度，页面会说明是哪些。汇率和费用不计在内，每笔交易不论大小都只算一次，所以它衡量的是判断，而不是金额。
- **方向对了**：有价格的交易中，顺向幅度超过 0.05% 的有多少笔（更小的变动视为没有变化），以及平均顺向幅度，分别按全部交易和每个标签统计。标签那一行把平均值画成从中线出发的条形：方向对了向右，方向错了向左。点选一个标签，会只针对这个标签重新读取复盘，页面上的每个数字都只关于它的交易；**全部交易** 可以回到全部。没有标签的交易那一行不能用来筛选。
- **卖出已实现盈亏**：Trading 212 在带记录的卖出上记下的已实现盈亏。
- **有日志的交易**：这段时间的成交中有多少笔带记录，其中多少笔写了复盘。
- **该写复盘**：有理由、还没复盘、且成交已满 30 天的交易。每笔都会注明，点 **写复盘** 就在这笔交易下面写一条，写的时候这笔交易一直留在视野里。

标签页跟随时间段切换（1个月、3个月、今年、1年、全部，或旁边日历按钮选的自定义区间），点标的名称会打开它的持仓页，持仓页的“返回”链接会回到日志。对应订单不在这段时间成交里的记录（仍在挂单、已撤单、在这段时间之前成交，或成交没有价格），以及没有关联订单的记录，会在底部计数。每个时间段读到的订单历史保留一分钟；发送或撤销订单会清掉它，所以新的成交在下次打开标签页时就会显示。从日志打开持仓页后在那里写的记录，点“返回”回到日志时就会显示。

`trade-journal` skill 会用上这些功能来复盘你的交易：它把你当时给出的理由和每笔交易的实际结果放在一起看，并把你从中得到的体会保存为复盘。

<a id="changing-and-deleting"></a>
## 修改和删除

`manage_trade_journal` 配合 `action: "update"` 和 `entryId` 可以修改理由、复盘或标签；没传的字段保持不变，传空值则清空，前提是记录仍保留理由或复盘中的至少一项。`action: "delete"` 删除记录。在持仓页上，**编辑** 和 **删除** 作用相同，删除会在原处再确认一次。

日志工具和价格提醒一样，不需要下单工具（`trade:write`）也能用，因为它从不交易。
